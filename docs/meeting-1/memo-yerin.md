# 메모 — 예린(프로덕트 디자이너)

## 1. 한 줄 제안
첫 화면은 "AI 도구 목록"이 아니라 **"이름 있는 팀이 한 사무실에 있다"는 느낌**으로. Codex 캐릭터 페이지를 영재단 브랜드(다크, ✦)로 옮겨 히어로로 쓰고, 한 명을 누르면 그 직원이 무슨 일을 맡는지 바로 보이게 한다.

## 2. 누가 보나 / 보고 나서 무엇을 하길 바라나
1순위는 YOUNGJAEDAN GitHub 조직에 들어온 개발자·지인(폰으로 링크를 여는 사람). 보고 나서 "이 팀이 어떻게 일하는지" 한 단계 더 보기(운영 방식 설명 또는 레포)로 넘어가길 바란다. 대상은 대표가 정할 일이라 질문 1로 남긴다.

## 3. 꼭 되어야 하는 동작 3개
- 390px 폰에서 첫 화면에 로고·한 줄 철학·팀 전체가 스크롤 없이 보인다
- 직원을 탭하면 이름·역할·하는 일 카드가 열린다(3D 없이 목록에서도 같은 카드)
- "어떻게 운영하나" 한 곳으로 이어지는 버튼 하나(44px 이상)

## 4. 일부러 안 할 것
지어낸 성과·진행률·"근무 중" 같은 실시간처럼 보이는 표시(실제 기록과 연결 전까지), 영어 위주 문구("Little Studio"), 시점 3종 전환을 판 1의 핵심 기능으로 두는 것, 문의 폼·가입.

## 5. "됐다"의 기준
- 390px·1280px 캡처에서 첫 화면 안에 로고·철학 문장·팀 전원이 보인다
- WebGL을 끄거나 `prefers-reduced-motion`이면 같은 내용이 목록으로 나온다(직접 확인)
- 본문 대비 4.5:1 이상, 탭 영역 44px 이상, VoiceOver로 직원 이름·역할 12개(대표 포함 여부는 확정 후)를 모두 읽을 수 있다
- 대표가 판 1을 눌러 보고 리뷰 포인트에 "좋음/바꿀 것/모르겠음"을 남겼다

## 6. 위험·주의
- 현재 캐릭터 페이지는 밝은 배경·WebGL2 필수·폰 라벨 7px라 그대로 쓰면 브랜드·접근성이 어긋난다. 캐릭터 그림체는 살리고 화면 틀은 새로.
- 3D 로딩이 폰에서 무거울 수 있음(용량·속도 알 수 없음) → 정지 이미지 먼저, 3D는 뒤에.
- "근무 중" 같은 장식이 실제 상태처럼 읽히면 정직 규칙 위반. 판 1 상태 표시는 모두 `샘플` 배지.

## 7. 대표에게 물을 질문
1. 첫 방문자는 누구? — 권장: 개발자·지인(폰), 투자·고객용은 나중
2. 캐릭터 12명에 "대표"도 넣나? — 권장: 넣되 직원과 구분(별 ✦ 표시)
3. 판 1 언어는? — 권장: 한국어 우선, 영문은 로고·부제만
